# 「猜哪个更早」互动游戏技术 Spec

状态：提案，未实施  
日期：2026-11-14  
产品：Things Atlas / 日常之物图志

## 1. 产品目标与规则

每次打开网站或刷新页面，页面中央通过轻量弹出动画出现一道题：随机展示两个日常物品，让用户猜哪个更早被使用。点击后原地揭晓，关闭即可继续浏览网站。

唯一判题口径：**本站收录的最早已知使用年份**。这是当前证据支持的记录，不宣称绝对首次使用或确切发明日期。

题目标题：「哪个更早被使用？ / Which came into use earlier?」
规则小字：「按最早已知使用年份比较 / Compare the earliest known use dates.」

直接展示题目，不设开始页、开始按钮、题号、计分、倒计时、下一题、再玩一次或成绩页。每个页面加载生命周期只弹一次；用户可不作答直接关闭。同年或无法可靠确定先后的组合不出题。

## 2. 数据现状与必要调整

现有 years 包含 invention / patent / mass_production / popularization。src/lib/primaryYear.ts 按 primary 指定字段或字段优先级生成 primary_year，并非取最小年份，更不保证最早使用语义。

因此禁止以下推断：

- 直接把 primary_year 当游戏年份。
- 对 years 的全部年份取 Math.min，当作最早使用年份。
- 在缺少使用记录时用专利年、量产年自动补位。
- 把精度为世纪的约数视为确切某年，生成相差几年的题。

### 2.1 新增独立的使用证据字段

在条目 JSON 中增加可选 earliest_use，并同步 JSON Schema、AtlasItem 类型及索引构建。该字段属于条目历史数据，不是仅供游戏使用的隐藏答案。

```ts
type EarliestUse = {
  year: number; // 与现有年份约定一致，负数表示 BCE，不允许 0
  precision: 'year' | 'decade' | 'century';
  range: { start: number; end: number }; // 已审核的年代上下界，含边界
  evidence: 'documented_use' | 'archaeological_evidence';
  explanation_zh: string;
  explanation_en: string;
  source_urls: string[]; // 必须引用该条目 sources 内的 URL
};
```

字段语义：year 为用于展示的代表年份，range 为当前证据支持的年代范围；确切年份 start=end=year。约数的范围须依据原资料人工确认，不机械转换为 year±50 或某个世纪边界。若资料只提供“早于某年”等开放范围而无法形成可靠比较，V1 暂不纳入。

证据可来自使用记载或考古实物，均需明确对应当前物品品类。原型或祖先工具不自动代表现代品类已存在，需先核实条目定义。新发明的实际演示/使用记录可以纳入 documented_use；单独的专利批准不能证明使用。

没有 earliest_use 的条目继续正常展示在地图，但不进题库。可以从现有 invention 的 ref/ref_zh 和 sources 提取候选信息供审核；迁移脚本不能自动标为已核实，更不能无依据填充范围。启用前至少有一对合法组合；推荐首批审核多种类别的条目以提供随机性，不再要求 20 个条目或整局匹配。

### 2.2 校验约束

1. year、start、end 均为安全整数且不为 0，start ≤ year ≤ end。
2. precision=year 时要求 start=end=year；约数必须保留约数显示，即使两者相距很远。
3. 中英解释都非空，推荐中文不超过 80 字、英文不超过 220 字符；超出先要求编辑，不随意裁掉限定信息。
4. source_urls 非空、无重复，且全部能在原条目 sources 中匹配。
5. disputed=true 或 confidence=disputed 的条目，V1 保守排除；不影响地图展示。
6. 数据修订更新条目 updated；不得为了扩题库放宽证据条件。

### 2.3 详情页一致性

有 earliest_use 的条目在详情增加「最早已知使用 / Earliest known use」行，显示相同日期、解释与来源。保留既有发明/专利/量产/普及节点和地图主年份；不要为接入游戏全局改变时间轴口径。

游戏中「查看条目」打开详情时应能找到同一证据，避免游戏和详情看似给出不同答案。

## 3. 自动触发与页面协调

### 3.1 触发范围

- 首页与独立条目页直接打开、浏览器刷新、新标签页访问：每次新 document 加载均触发一次。
- 站内选条目、切语言、拖时间轴、组件重渲染、窗口重新聚焦：不触发新题。
- 从浏览器前进/后退缓存（BFCache）恢复同一个 document：保持原状态，不再次弹出。
- 不写 localStorage / sessionStorage 来抑制后续刷新；不是每天一次或每个浏览器会话一次。
- 不增加 SiteHeader 游戏入口，也不增加公开路由或 URL 参数。

### 3.2 显示时机

客户端 hydration 完成后异步加载题库与弹窗组件，等待首屏绘制；在页面可见、组件及题目就绪，且首屏绘制后至少 600ms 时显示。600ms 是视觉缓冲，不要求地图、瓦片或物品图片加载成功。

页面处于后台时等待 visibilitychange，回到前台再检查；已关闭的题目不会因可见性变化重开。数据加载失败时本次访问直接跳过，不展示空弹窗、不阻塞页面、不循环重试。

以 document 生命周期共享的客户端控制器记录 pending/open/consumed，而非只依赖可重置的组件 state。所有定时器、监听清理必须幂等；React StrictMode 的 effect setup/cleanup/setup 不能造成重复抽题、弹两次或永远不弹。初始化随机题的结果缓存到本次 document，SSR 不创建该控制器。

### 3.3 与引导、其他弹窗协调

App 管理自动弹层顺序。自动猜题处于等待或展示期间，暂停 Guide 的自动邀请及其已排定计时器；只依赖现有 dialog[open] 检查不足以避免延迟计时器竞争。

本次访问安排自动猜题后，不在关闭猜题时紧接着弹出新手引导；本次 document 的自动引导邀请跳过，但不写入“引导已完成”，用户仍可通过帮助按钮主动打开。

若用户先主动打开更新记录、分享或帮助，则等待该弹层结束，再显示尚未消费的题；不覆盖或嵌套弹窗。Guide 增加由 App 传入的自动邀请开关，并取消关闭状态下的旧计时器。

弹题不会修改地图时间、筛选、当前条目或 URL。更新记录本身仍保持“加载和刷新不自动弹出”的原约定。

## 4. 单题界面与交互

### 4.1 答题前

原生 dialog 居中，顶部标题与关闭按钮，下面两张物品卡，底部一行规则和「跳过，浏览地图 / Skip and explore」。桌面两卡并列；窄屏优先保持可读，必要时上下排列，弹窗内部可滚动。

卡片只展示图片、当前语言名称，整卡为 button。不展示年代、历史简介、地域等提示。alt 使用名称；图中文字含年份的素材禁用或使用中性占位。图片失败不影响根据名称作答。

关闭按钮、Esc、跳过和点击遮罩均可退出；点击弹窗内容不能误关闭。无退出确认，退出后本次 document 不再弹出。

### 4.2 点击揭晓

第一次有效选择后立刻锁定两卡；双击与重复键盘事件不能改变答案。原卡片区域展示：

- 「答对了！ / Correct!」或「其实，X 更早 / X came earlier」。
- 两个物品各自的最早已知使用年份，约数保留「约 / c.」。
- 每件物品一句简短依据，以及来源链接。
- 正确选项带明确文字和图标，不能只依赖颜色。

揭晓不自动关闭，让用户自行阅读。底部主按钮为「继续探索 / Keep exploring」，点击关闭弹窗。两件物品分别提供「查看条目」：关闭弹窗后沿用 App 的条目选择流程进入对应详情，本次访问不再显示题目。

来源在新标签页打开；返回时保留揭晓状态。没有下一题、分数或独立结果页，不默认展示“早了多少年”。

### 4.3 语言

初始语言跟随当前站点。无需另加游戏语言控件；若应用语言变化，原题文字同步切换，不能重新抽题、交换左右或清空选择。

## 5. 中央弹出动画

动效应体现“从页面中间跳出一题”，不是从底部滑入的抽屉：

1. 遮罩约 180ms 从透明变为低透明度暗色，保留背景地图可见。
2. 内容以自身中心为 transform-origin，约 360ms 从 opacity:0、scale(.88)、translateY(12px)，经 scale(1.025)，收至 scale(1)、translateY(0)。
3. 两张物品卡随主体一起出现，不做额外飞入，避免视觉杂乱。
4. 答后年份/解释在约 180ms 内淡入；提前预留合理空间，避免剧烈跳高和焦点偏移。
5. 关闭约 160ms 淡出并缩至 .97，完成后释放遮罩与焦点；超时兜底确保 animationend 未触发也能关闭。

使用 CSS transform/opacity 和现有 token，不新增动画库，不动画修改 width/height。动态减少偏好下取消缩放与弹性，使用极短淡入或直接显示；业务状态不依赖动效结束。

焦点初始放在题目标题或关闭按钮，不默认放在答案上。关闭回到打开前的有效元素，若不存在则回到站点标题/主要导航。选项支持 Tab、Enter、Space；结果使用 aria-live=polite，揭晓后焦点进入结果说明。弹窗打开时背景快捷键不得穿透。

## 6. 随机选题

### 6.1 构建合法组合

按 id 排序合格条目，枚举不同条目的无序对。只有以下条件之一成立才纳入：

```ts
a.earliest_use.range.end < b.earliest_use.range.start // A 更早
b.earliest_use.range.end < a.earliest_use.range.start // B 更早
```

同年、范围重叠、边界相接及争议条目排除。负数直接比较，-3000 早于 -1000，不比较绝对值。

data/quiz-excluded-pairs.json 记录品类范围难比较的组合和人工原因；校验引用存在、两者不同、无重复。候选池独立于当前地图筛选。

### 6.2 每次加载只抽一次

从合法组合数组中均匀随机选一对，再以 50% 概率交换左右。允许注入 RNG 以便测试；生产使用 Math.random 即可，无奖惩或防作弊需求。

不先无限随机选两个再反复重试，不再使用整局回溯匹配、fallbackRound、20 个唯一物品或左右各 5 题的逻辑。每次刷新重新抽取，但随机可能重复上一题；V1 不保存历史，也不承诺刷新必定不同。

构建生成题库及 datasetVersion，至少有一对合法组合才能启用。当前数据规模使用无序 id 对数组即可；详细内容每个条目只存一份，不在每对中复制说明和图片。

## 7. 状态与工程接入

```ts
type Question = { id: string; leftId: string; rightId: string; earlierId: string };
type QuizState =
  | { phase: 'pending' }
  | { phase: 'question'; question: Question }
  | { phase: 'revealed'; question: Question; selectedId: string }
  | { phase: 'dismissed' };
```

question 与 revealed 可关闭并进入终态 dismissed；pending 加载失败也进入 dismissed。终态不允许重新打开。ANSWER 只在 question 且 questionId 与选项合法时有效；不维护答案数组、题号或分数。

| 文件 | 职责 |
| --- | --- |
| data/items/*.json、JSON Schema、src/lib/types.ts | earliest_use 及类型 |
| scripts/validate-items.ts / scripts/build-index.ts | 证据校验与索引字段 |
| scripts/build-quiz.ts | 合格条目、合法组合、datasetVersion |
| data/quiz-excluded-pairs.json | 语义上不适合的组合 |
| src/generated/quiz.json | 生成题库，按现有生成产物约定 ignore |
| src/lib/quiz.ts | 比较和单题随机抽取纯函数 |
| src/lib/quizLifecycle.ts | document 级一次性抽题/弹出控制，SSR 隔离 |
| src/components/QuizDialog.tsx | 单题、揭晓、动画、关闭 |
| src/components/Guide.tsx | 自动邀请暂停及计时器清理 |
| src/components/ItemDrawer.tsx | 最早使用证据展示 |
| src/App.tsx | 启动调度、弹层协调、打开条目回调 |
| i18n 与字体扫描脚本 | 界面文字和证据文字覆盖 |

构建顺序：数据校验 → build:data → build:quiz → 前端打包 → 现有预渲染。开发启动同样准备题库。源数据与模板提交 Git，生成产物按现有约定管理。

组件和题库在 hydration 后异步加载，不阻塞 HTML 首屏，也不等待用户点击才加载。SSR 不输出自动弹窗或随机题目，避免水合不一致。只请求所抽两件物品的图片，不预加载全题库。

## 8. 验收标准

### 规则与数据

- primary_year / 专利年不能自动当最早使用年；无证据字段的条目不进题库。
- 同年、范围相交、边界相接、争议及人工排除组合均不出题。
- BCE/CE、约数、缺解释、非法来源引用、年份越界有覆盖测试。
- 注入固定 RNG 能验证选对与左右交换；抽题不循环重试，不要求连续刷新不重复。
- 题库为空时构建明确报错；运行时加载失败静默跳过，不影响网站。

### 自动显示

- 直接打开首页、中文/英文条目页、新标签页和刷新均弹一题。
- 同一 document 重渲染、切语言、切条目、重新聚焦不重复弹题；BFCache 恢复也不重弹。
- StrictMode 和控制器组件重挂载不重复抽题、不泄漏计时器，也不会误吞首次弹出。
- 后台打开等前台显示；关闭后再切前后台不会重开。
- 地图失败、瓦片超时或题目图片失败不妨碍文字答题。
- 新手引导不会与题目叠加，也不会在关闭题目后马上接着弹；主动帮助功能仍可使用。

### 交互与视觉

- 直接出现两件物品，无开始页、题数、积分、下一题或结果列表。
- 动画从屏幕中央弹出，主体稳定，不挡住关闭按钮；减少动态效果偏好正确降级。
- 双击只接受首次选择；揭晓后不能修改答案，不自动跳转或关闭。
- 关闭、Esc、遮罩、跳过、继续探索均只结束本次提示；查看条目打开正确详情。
- 中英长文字、无图、窄屏不会溢出；键盘与屏幕阅读器可完成选择和退出。
- 弹窗前后的地图状态保持；只有用户明确点击查看条目才改变所选条目。

实施时完成数据/字体验证、比较/随机/生命周期专项测试、交互验收和适用构建检查，不运行全项目类型检查。发布仍遵守现有更新日志与 push 确认流程。

## 9. 完成定义

每次新打开或刷新网站，只在中央弹出一道合法的随机二选一题；用户可猜、可跳过，答后看到年份和依据，关闭即回到原来的浏览状态。不包含连续闯关、计分、战绩海报、账号或后端。
